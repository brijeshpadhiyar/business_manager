## 1. Flexible Lot Structure (Module 1)

StitchFlow now supports both **Colour-Only Lots** (Design optional) and **Design-Based Lots** (multiple designs × multiple colours) within the unified `lots -> lot_designs -> design_colours` hierarchy without duplicating inventory tables:

- **Colour-Only Lots**: Users tap **Add Colour (No Design)** directly on any Lot (`LotRepository.addColourDirectlyToLot` / `LotDetailCubit.addColourDirectly`). Under the hood, an implicit container design (`kColourOnlyDesignSentinel = '__NO_DESIGN__'`) is auto-managed and rendered cleanly in UI as **"Colours (No Design)"** (and variant labels display `"Red"` instead of `"__NO_DESIGN__ • Red"`).
- **Design-Based Lots**: Unlimited designs per Lot and unlimited colours per design, with independent quantities and unit prices.
- **Automatic Totals**: `LotDetailPage` and `JobProcessRoutingPage` automatically compute Lot-wise, Design-wise, and Colour-wise totals.

## 2. Variant-Level Process Management & Splitting (Module 2)

Every operation (`job_processes`) and handover (`process_handovers`) tracks exact `lot_id`, `lot_design_id`, and `design_colour_id`:
- Multiple workers can receive independent splits of the exact same variant (e.g., `D-101 Red: 100` -> Dharmesh `60`, Ramesh `40`).
- A single worker can hold multiple variants simultaneously (e.g., Dharmesh holds `D-101 Red: 60` + `D-101 Blue: 100`).
- Direct worker-to-worker transfers (`directTransfer`), Factory returns (`returnToFactory`), and Factory reassignments (`reassignFromFactory`) preserve full design & colour variant metadata and prevent quantity mismatches across all operations.

## 3. Dynamic Process Pricing, Configurable Units & Rate History (Modules 3 & 4)

### Schema v5 Additions (Zero Duplicate Ledgers)
1. **`processes`** (additive columns):
   - `default_rate_paise` (`INTEGER NOT NULL DEFAULT 0`)
   - `default_pricing_unit` (`TEXT NOT NULL DEFAULT 'PER_PIECE'`)
2. **`job_processes`** (immutable assignment pricing snapshots & payment tracking):
   - `default_rate_paise`, `agreed_rate_paise`, `pricing_unit`, `rate_override_reason`
   - `payable_amount_paise`, `paid_amount_paise`, `payment_status` (`PENDING`, `PARTIALLY_PAID`, `PAID`)
3. **`process_additional_charges`** (new v5 table):
   - Supports `EXTRA_CHARGE` (urgent work, special cutting) and `DEDUCTION` linked to `job_process_id`, `lot_id`, `design_colour_id`, `member_id`, with unique partial `client_request_id` duplicate guard.
4. **`process_rate_history`** (new v5 table):
   - Immutable audit log of every `PROCESS_DEFAULT` change and every `JOB_ASSIGNMENT` rate override (`previous_rate_paise`, `new_rate_paise`, `pricing_unit`, `reason`, `changed_by`, `changed_at`).

### Pricing Engine (`ProcessPricingCalculator`)
- **Configurable Pricing Units**: `PER_PIECE`, `PER_DOZEN` (exact half-up integer paise division: `(qty * rate + 6) ~/ 12`), `PER_LOT`, `FIXED_AMOUNT`, and extensible custom unit strings.
- **Immutable History**: Updating a process's default rate (`updateProcessDefaultRate`) records history and NEVER alters existing job assignments.
- **Mandatory Override Reason**: Changing `agreedRatePaise` away from `defaultRatePaise` strictly requires `rateOverrideReason` (`rate_override_reason_required`).
- **Unified Payment Ledger**: `recordProcessPayment` atomically inserts a `REGULAR` payment into StitchFlow's existing `payments` table and updates `job_processes.paid_amount_paise` + `payment_status` (`PENDING` -> `PARTIALLY_PAID` -> `PAID`).
- **Exact Cost Summaries (`JobCostSummary`)**: Computes Worker-wise payables, Process-wise expenses, Design-wise costs, Colour-wise costs, Additional charges, Deductions, Paid, and Outstanding amounts in integer paise.
